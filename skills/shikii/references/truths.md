# Rules for truths, calibration and the judge

- The usual agent's provisional scoring is `shikii review` (`shikii_review` over MCP). It takes the conversation, scores scope and completion, and holds items whose grounds are not enough. It saves to `records/reviews/` and is not mixed into the truth labels or calibration below. A score that agrees with the decision model's answer becomes a machine truth (source `agreed`, never the person's); only disagreements and held items go to the person (0.11). Feed corrections back into the next scoring. Steps are in [review.md](review.md)

- Where a truth comes from (source): `ui` / `manual` / `ask` / `audit` / `outcome` are a person or the outcome. `context` (the answer of the rung above), `judge` (the judge) and `agreed` (the decision model and the agent gave the same answer, 0.11) are machines. `replay` / `file` only re-took the probability; the truth is still the person's
- Outcome truths from the hooks (source `outcome`; the AI's interpretation is not used): prompt-kind is whether the working tree changed between requests. changes-in-scope is no (weight 1) if a changed file is reverted before the person's next request, and yes (weight 0.5) if it is still there at the request after that. done-as-asked is no (weight 1) if the person's next message restates the same request, yes (weight 0.5) if it is clearly a different request, and short replies and the middle range get no label. Decisions that get an outcome do not wait for a person even when unsure
- When no line can be drawn: if truths reach `min_n` and automatic calibration could not write a line, the hook asks the agent for candidate ways of asking (`shikii hook variants submit`, at most 3). Automatic calibration with the same wording and model is not repeated until truths grow by 20. For a candidate that did better, the hook asks for a meaning check before the next request. Check whether the two ways of asking ask the same thing (whether the same answer is correct in every case), translate both into the language of the person's setting (no translation needed if it is English), and pass `{spec, run, verdict: same|unsure|different, current_translation, candidate_translation, difference}` to `shikii hook variants check`. If same, it is adopted, and the person is told (with the translations) and can revert it. When the meaning changes even slightly, or you cannot decide, write unsure and the difference (ask the person)
- Conditions for writing a line: human truths at or above `min_n`. A line is not written from machine truths alone. `check` also looks at act's precision on human truths alone
- Re-asking (replay): even when the wording or the model changes, calibrate re-asks the truths whose text is still kept, under the current hash. No person is needed
- The judge (`shikii judge`): asks a different, larger model the same spec. It first measures the agreement rate with human truths, and only a judge that reaches act puts truths with weight = agreement rate on records without an answer. If the judge is also unsure, it goes to a person. The judge does not replace human truths (people inspect the judge by sampling)
- Adopting with tune: only when the holdout beats the current one, a one-sided sign test gives p ≤ 0.05, and a person has also confirmed "the meaning is the same". You type `--write` only after the person has read that candidate and agreed
- wiki (`.shikii/wiki/`): the Rules in `wiki/specs/<id>.md` are that decision's detailed rules (written by a person). `wiki/patterns/` holds claims (claim / applies_to / evidence / retest). tune's winner goes into `wiki/patterns/drafts/` as a draft. Only a person changes the state. `shikii wiki verify` re-verifies with the current model and can add evidence
