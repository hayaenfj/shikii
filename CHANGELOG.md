# Changelog

**English** · [日本語](CHANGELOG_ja.md)

## 0.9.3 — Small fixes after 0.9.2

- Codex MCP, one shared server: Codex reads shikii's MCP server only from the shared `~/.codex/config.toml` and starts it in the folder its background service started in. The form init wrote (`args = ["mcp", "--store", ".shikii", ...]`) stopped before the handshake when that folder had no shikii project ("no spec (*.yaml) in .shikii/decisions"), and an absolute store made every session use one project. Now `shikii mcp` always answers the handshake and the tool list, even without a project, store or specs; every tool takes `project`, the absolute path of the agent's working folder, and uses that project's `.shikii/` for the call (only projects initialized on this machine whose store passes the usual checks; others are refused with a tool error). Without `project` it uses the store it was started with (Claude Code and OpenCode, unchanged), and without one the tool error says to pass `project`. init writes Codex's registration as `command = <this binary>`, `args = ["mcp"]`, and init and the update rewrite the blocks 0.9.1 and 0.9.2 wrote to it. A block a person edited is left alone; when it names one project's store by an absolute path, the update says so and suggests `args = ["mcp"]`. The MCP instructions and the skill tell agents to pass `project`.

- Codex MCP server: the update and init point `[mcp_servers.shikii]` at the running binary's path (as the hooks do) when the block is still exactly what shikii wrote and its command is the bare name `shikii` (0.9.1 and earlier) or a path that no longer exists. Codex started from a desktop app may not have `shikii` on its PATH. A block a person edited, another existing binary, or two shikii blocks are left alone. The PATH lookup is only a fallback when the binary's own path cannot be read.
- Page and hook, words: texts that count or keep every truth (the learning count, the wording match, "on hold" and "failed" when setting the point, "ask the AI again", the how-to guides, the wording notices of the hook) no longer call them "your answers", since truths sent by the agent and from results are counted too. "Your answer" stays only on a card the person answered and on Answer. The Japanese wording notices name the question by its title on the page instead of its id and the candidate's name, and no longer use the inner word for a decision.
- Page, learning count: the number of truths shown for each question (`keys[].n` in `/v1/status`) is now the number the AI's point is set from: the newest truth per conversation, from people and results only. Before, it counted every label, including the machine's own (context, judge) and each re-answer of the same conversation, so it could read "enough" while no point could be set.
- Hook, notices about the AI deciding alone: the end-of-turn notices (enough truths with one answer only, the point was set, the answers could not be told apart) name the question by its title on the page in English and Japanese, not by its id. The Japanese text uses the page's plain words instead of the inner words for decisions, lines and spot checks, and gives the counts per answer by the page's answer names.
- Hook, wording notices (English): the question is named by its English title, and the new wording is shown by its question text instead of the candidate's internal name.
- Skill: the examples in `references/guards.md` (forbidden words and the words a commit body must contain) are in English, so an English setup reads no Japanese there.
- Reflection, `left`: a submit that only assesses a lesson delivered to a subagent now says what is left for the parent conversation (the delivery has its own id). When shikii cannot work out what is left, the reply says so in `left_error` instead of dropping `left` as if nothing were left.
- Wiki, corrections: a refused `correction` now says why. A correction must quote the person's reply in a conversation the hook recorded; a captured source (even `kind: "human"`) is refused with a line saying to save the lesson without `correction` and cite the source, which is what an agent without hooks can do. The check itself is unchanged.
- Tune: a run tuned with a relative spec path (for example `shikii tune .shikii/decisions/x.yaml` from the project folder) saves `spec_path` as an absolute path, so the page and the hook can adopt it when they run from another folder. A moved project folder is still followed as before.
- Wiki sources: the long text of a conversation (`originals`, up to 2 MB) that does not fit in one reply now comes in parts with `original_part` (`id`, `from`, `to`, `bytes`, `json`) and `next_cursor`, like a long captured source. Before, it came whole in one reply, far over the reply size. The `json` pieces joined in order are the JSON of that conversation's originals.
- Hook, the other lines for the person: the unsure line and the end-of-turn lines for "changes outside what you asked" and "not finished" now name the question by its title on the page (as the other notices do since 0.9.3) and give the AI's confidence as a percent instead of the spec id and `p(yes)=0.10`; the Japanese lines and the waiting-answers line use the page's plain words. The context for the agent keeps the id and p.
- `shikii status`: the count on each (model, wording) line is now the page's learning count, the truths calibration uses (the latest per input, from people and results only), instead of every label; machine truths and a re-label no longer raise it. The line shows one number: `3  collecting (min_n 50)` instead of `6  collecting (3/50)`.
- Page tests: the check that counted truths are not called "your answers" is now an allowlist over every dictionary text (only the texts about the person's own answer may say so), so a new text cannot slip past it.

## 0.9.1 — Three pages: Answer, Knowledge and The AI

- Page: the per-question menu on the left and the summary bar at the top are gone. The switch at the top has only "Answer" (with a count of the decisions waiting for you), "Knowledge" and "The AI". On first open it starts on Answer when something waits for you, otherwise on Knowledge, and the page you picked opens next time.
- Answer: what waits for a person across the four questions you answer is merged into one queue and shown one card at a time. The question appears at the top of the card and above the buttons, and the button bar sticks to the bottom of the screen (long conversations no longer push the buttons out of view). Bands, model marks, number cards and filters are not shown. Questions only the AI answers, and records whose truth comes from results, are not shown. Only when a new wording waits for adoption does this page ask whether it means the same. The keys (1-9, Enter, →) work only on this page.
- The AI: one line per question with how far it has learned; pressing it opens that question (progress, the last calibration, the lane switch, reviewing and changing past answers, wording candidates). The lessons delivered and the routine, the guards, the decision model and how often it waits for a person are here too. The cluster of model and count pills beside the question title, the three number cards, the project and kind filters and the one-by-one / list switch were removed.
- Section headings sit in a light grey band with dark bold text and a green bar, so they no longer blend into the items below.
- Lesson delivery: a subagent (Claude Code's Agent tool) now gets lessons chosen by the task its parent handed it. A hook just before the Agent / Task tool (`PreToolUse`, `shikii hook agent-task`) keeps the task text and the subagent type, and when the subagent starts (`SubagentStart`) the oldest kept task of the same type is used. When a task is kept, earlier tasks of the same type older than 30 seconds are dropped (subagents that were refused and never started; a task without a type counts as general-purpose). The subagent side carries no call id, so re-launching the same type within 30 seconds of refusing the Agent tool can still pick the refused task's text. Without a kept task it does not choose by the parent's request; it delivers only rules whose scene is "いつも" (or "always"). Before, lessons were chosen by the parent's request and unrelated ones reached the subagent (in this project's records, 4 of 37 deliveries to subagents helped). The update adds a fourth hook to Claude Code (not to Codex; other people's PreToolUse groups are left alone).
- Lesson delivery: history (`history`) articles are no longer delivered automatically, before requests or to subagents (in this project's records they were delivered 7 times and never used). They can still be read by searching (`wiki query`). Articles without a kind (from before the update) are delivered as before.
- Habits: when the agent itself creates or changes a rule, test or procedure (a command, a script), it writes it to the wiki in the same turn even if nobody asked, as a howto or rule page (adding to or editing the closest page). Before, the habits only asked it to save what the person corrected or decided, so procedures it made lived only in the repository and its reply. To reach agents that do not read the skill, the rule is in the skill, the once-per-session habit notice, the planning notice sent with every request, the reflection request, the shikii section of AGENTS.md and the MCP instructions (the AGENTS.md section is replaced on update).
- Reflection: `reflect submit` (MCP `shikii_reflect`, `/v1/reflect`) no longer limits how many conversations (2), items (4 provisional assessments, 2 wiki drafts, 4 memory assessments) or article reviews (2) it takes at once. The only limit left is the input size, raised from 64 KB to 1 MiB (the same as a work-record write; 64 KB filled up with one to three large drafts). When it is exceeded, the reply says to split the drafts and send the rest in the next submit. Before, the existing sources of a page being extended were counted as conversations, so a page with three or more sources could not be updated through reflection. Saving keeps the existing sources. `reflect query` still shows the oldest two conversations at a time.
- Knowledge: the `rule` kind is renamed from "Rules to keep" to "Rules decided in this project", and a panel with that name sits at the top of the Lessons tab. It lists every rule set by people or by the AI, whatever scene is picked, so rules the AI made are visible to people and none gets buried. "Always" rules come first, then the newest; rules added or changed in the last 7 days are marked "new". The hook and MCP texts and refusal messages use the new name.
- Answer: answering lowers "N left" and the count beside "Answer" at once (before, they changed only at the next 15-second reload). Answering while a reload is in flight no longer brings the answered card back from the old response. The folded section inside Knowledge is renamed "Detailed records of the articles" so it is not confused with the new "The AI" page.
- Cards: Markdown bold and heading marks in the agent's reply are removed for display (no HTML is rendered; also inside the folded previous reply). "Spot-check an AI assessment" now reads "A spot check of a decision the AI made alone", and "The AI could not assess this" reads "The AI could not decide this one".

## 0.9.0 — Look up knowledge by scene and kind

- **Update note:** articles given a kind and scene by 0.9.0 look "changed" to a 0.8 binary, and 0.8 refuses every save to the wiki (the articles are not damaged). After updating, reopen the open agent sessions (and their MCP), and update every machine that uses the same wiki to 0.9.0. The update prints this note at the end.
- Kinds and scenes of articles: an article with a lesson needs a `kind` (`rule` a rule to keep, `howto` a how-to, `criteria` criteria for a choice, `fact` a fact or assumption, `history` history) and a `scene` ("when …" in the words of the work, up to 24 characters). `wiki ingest` and `reflect submit` (CLI, MCP, HTTP) all refuse a save without them, and the refusal lists the values to use. When an update leaves them out, the previous revision's values are kept. The input shapes of MCP's `shikii_reflect` and `shikii_wiki` show both fields and their values.
- Reflection's `place` returns the scenes in use with their article counts (`scenes`, up to 30, most first), and each candidate carries its kind and scene. The agent reuses a close scene's wording.
- Earlier articles: articles made before 0.9.0 have no kind or scene. The request hook lists five at a time (id, title, lesson, when it applies, and the scenes in use) and has the agent set them with `shikii wiki classify <page ID> <kind> <scene>` (`operation: "classify"` on MCP's `shikii_wiki`). The lesson text is not changed, and the result is kept as a new revision. If the article is edited meanwhile, classify refuses (an edit is never undone by the old lesson), and the previous change reason is kept. While the wiki has an unreadable or hand-edited article, no articles are asked for; one line suggests `shikii wiki lint` instead (no block). If the agent tries to end with listed articles still unset, Stop blocks once (the built-in routine check `wiki-kinds`, shown under `rituals:` in `shikii status` and as `kinds` in `/v1/status`). The `wiki query` listing also returns how many remain and the next five.
- Reaching agents without hooks: the reply of `wiki query` starts with the unclassified notice (`unclassified_how`, `unclassified_count`, the next five), and the replies of `wiki ingest`, `wiki classify` and `reflect submit` carry what remains (left out once none remain). ## 0.8.3 — Tell the person when a line is drawn, or why it cannot be

- Wiki placement truths: a draft merged into an existing page usually has its lesson rewritten (and is often saved with `wiki ingest`), so the placement judgment got no truth; only "made a new page" outcomes were labeled, every truth was "no", and no line could ever be drawn. Now `reflect submit` and `wiki ingest` (CLI, MCP, HTTP) both record the outcome. A saved draft matches a placed one when its lesson is the same; otherwise only a merge or replacement matches, and only a draft placed within 24 hours that had that page among its candidates and whose placed lesson mostly (60% of its word pairs; space-separated scripts such as English are compared by words, Japanese by characters) appears in the saved title, lesson and body. The best-covered draft wins (the newer one on a tie), so when two drafts are placed at once, the merged one is usually labeled. When a merge keeps the page's lesson and only adds to the body, the page's own old placement record is not taken as an exact match. Placed records whose candidate pages are gone are ignored. A new page never matches loosely, so unrelated saves do not label abandoned drafts.
- Line states: once the truths reach `eval.min_n`, `shikii status` and the page no longer just say "ready to calibrate". - The Stop hook tells the person once (a line in the terminal in Claude Code) when a line is newly drawn and when there are enough truths but no line can be drawn, with the reason. The wording depends on the question: for the question a person answers (needs-plan), the rest still asks; for the hook questions settled by results, the rest waits for results; for the wiki questions nothing is asked and lessons are never replaced silently. When answers cannot be separated, the hook questions ask the agent for other wordings; the others are tried again as truths grow. Once per question; again only when the state, the wording or the model changes.

## 0.3.0 — Grow a wiki from everyday conversations

The regular agent turns requests, AI replies and subsequent human messages into lessons with applicability conditions. shikii manages sources, the index, earlier revisions and history, then quotes lessons for similar requests. No wiki-specific UI work or additional resident model is required.

- **Ingest:** hooks provide up to two unprocessed conversations for the agent to organize through MCP `shikii_wiki` or `shikii wiki ingest`. Conversations without a reusable lesson, such as an additional request, can be archived as processed while retaining their source text.
- **Search:** `query` returns lessons, unprocessed conversations and original sources from the same project. Short search terms can find long lessons. The knowledge view also shows lessons and sources.
- **Update:** updating a lesson preserves its sources and previous revisions. Replacing an old lesson makes references use the new one. Replacement can be undone, and reverting content still leaves a history entry.
- **Check:** `lint` verifies source hashes, generated pages, revisions and links, and repairs the generated index. Runs once a day at the end of a turn as well.
- **Distinguish certainty:** all lessons are hypotheses with sources. Excludes lessons whose sources are missing or changed, and does not count AI interpretations as human answers or calibration samples.
- **Check versions:** aligns `shikii version`, MCP and the plugin at `0.3.0`.

The workflow of retaining sources, having AI edit a wiki, and running ingestion, search and periodic checks draws on [Andrej Karpathy's LLM Wiki idea](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f). Combined with shikii's claims, evidence and retesting, it distinguishes conversational interpretation from verified results.

Existing users can update the executables and agent instructions to use this through the existing two hooks. New MCP tools appear when the server next starts. Until then, agents can use the CLI commands supplied by the hooks.
