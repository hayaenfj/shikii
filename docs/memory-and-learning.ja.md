# shikii とメモリーの違い

## ひとことで言うと

「前に話したことを覚えておく」ところは、ChatGPT や Codex のメモリーと同じです。shikii は、その先で次の 3 つをします。

1. **覚えたことを、必要な場面でエージェントに届けます。** 依頼を始める前や、ファイルを変える直前に、関係する知識を渡します。
2. **届けた知識が役に立ったかを振り返り、知識を直します。** 役に立たない知識は届けるのをやめ、間違っていれば出典を確かめて直します。
3. **AI に任せてよい範囲を、実際の結果から決めます。** あなたの答えや確かめられた結果と AI の判断を比べ、AI だけで決めてよい場面と、あなたに確認する場面を分けます。

目的は、同じ説明や訂正を何度も繰り返さなくてよくすることと、プロジェクトに合った働き方を育てることです。

## 例: 「説明書は日本語版と英語版を一緒に直して」と伝えた場合

メモリーは、この言葉を覚えて、次の会話の参考にします。ただ、実際に両方を直したかまでは分かりません。

shikii では、次のように扱います。

- この決まりを、いつ使うかと出典(あなたがいつ何と言ったか)を付けた記事として保存します。
- 説明書を直す作業の前に、その記事をエージェントに届けます。
- 作業の後、エージェントはその記事が役に立ったかを振り返って記録します。
- 「両方のファイルを変えたか」のように機械で確かめられる部分は、あなたが有効にした検査で、作業の終わりに確かめます。片方しか直していなければ、エージェントは作業を終えられません。

## 比べると

| | メモリーでできること | shikii が加えること |
| --- | --- | --- |
| 覚える | 前の会話の文脈、好み、プロジェクトの慣習を覚える | 使う場面と出典を付けて、記事として残す |
| 使う | 次の会話や作業の参考にする | 依頼の前やファイルを変える直前に、関係する記事を届ける |
| 守らせる | 必ず守らせたい指示は `AGENTS.md` などに書くよう案内されている | 機械で確かめられる決まりを、作業の終わりに検査する |
| 直す | 覚えた内容を見たり消したりできる | 役に立ったかの振り返りをもとに、届けるのをやめたり、記事を直したりする |
| 任せる | 覚えた文脈を踏まえて答える | AI の判断と実際の答えを比べて、AI だけで決めてよい範囲を決める |
| 共有する | アプリごとに保存先と設定がある | 同じプロジェクトにつないだ Claude Code・Codex・OpenCode で、同じ知識を使う |

## shikii の中で回っている 2 つの流れ

### 1. 知識を使って、手入れする

1. **残す。** あなたが伝えた目的、選んだ方針、訂正、確かめた結果を、プロジェクトの `.shikii/` に保存します。記事には「どんな時に使うか」と出典があり、後から理由を確かめられます。
2. **届ける。** 仕事の始めや、関係する操作の前に、必要な記事をエージェントに渡します。
3. **振り返る。** エージェントは、届いた記事が実際の行動にどう影響したかを記録します。「届いた」「作業が成功した」だけでは、役に立ったとは数えません。
4. **直す。** 同じ場面で何度も使われなかった記事は、その場面へ届けるのをやめます。間違いや古くなった所は、出典を確かめて直します。あなたも画面から記事を編集・削除できます。

似た依頼の前に示すあなたの過去の回答も、同じように扱います。2 回以上使われず、一度も役に立っていない回答は示さなくなり、画面の知識欄の「AI が無効と判断した過去の答え」に並びます。この判断は、画面の「元に戻す」で取り消せます。

この流れの上に、次のことも積み重ねています。

- 作業の途中で分かったことを、同じ作業の記録に足せます。
- 前に使った手順は、そのときの条件・失敗・直し方と一緒に読み、今回の条件と比べます。前の成功を、そのまま今回の成功とは見なしません。
- 知識が届かなかった時は、その理由(検索に合わなかった、すでに届いていた など)を当時の記録から調べ、記事を直してから、過去の場面で試せます。
- 複数のエージェントで作業する時は、ひとりの発見をほかの担当に届け、別の条件で確かめて、同じ知識に戻せます。調査・実装・確認と担当が替わっても、確かめた条件と残る疑問を引き継ぎます。
- どれだけ読めば足りるかや、調査の進め方も、実際の結果から選び直します。別の 2 つの仕事で確かめてから採用し、悪くなったら前のやり方に戻します。

### 2. 判断を測って、任せ方を変える

- 「この依頼は終わったか」のように繰り返す判断について、AI が出す確率と、あなたの答えや実際の結果を比べます。
- 十分な記録がたまり、AI の自信と当たる割合が合っていれば、「ここより上なら AI だけで進めてよい」という線を引きます。線が引けるまでは、自動では進みません。

育つのはプロジェクトの知識と判断の基準です。AI 本体を学習し直すわけではありません。

## できないこと・言えないこと

- 振り返りはエージェントによる評価です。あなたの答えや、性能が上がったという測定結果とは分けて保存します。
- 知識をたくさん読んだことは、仕事が良くなった証拠にはなりません。
- 検査が確かめられるのは、機械で調べられる部分だけです。たとえば「両方のファイルを変えたか」は確かめられますが、文章が分かりやすいかまでは保証しません。
- 知識や AI の判断は、操作の許可にはなりません。今の依頼と、エージェントの権限の設定が優先されます。
- 速く・軽くした変更は、shikii が知識を渡す量や読む回数を減らすものです。モデル全体の応答時間や回答の品質が上がったという意味ではありません。

## OpenAI のメモリーについて(比べた範囲)

OpenAI の公開説明では、メモリーは好みだけでなく、繰り返す作業やプロジェクトの慣習など、前の会話の文脈を次の仕事へ持ち越すものです。ChatGPT のメモリーと Codex のローカルメモリーは、別の保存先と設定を持ちます。Codex のローカルメモリーには、前の会話をもとにした要約や出典も含まれます。そのため、「OpenAI は好みしか覚えない」「shikii だけが手元に保存する」という分け方は正確ではありません。

OpenAI も、必ず守らせたいチームの指示は `AGENTS.md` などに書き、メモリーだけに頼らないよう案内しています。

ここで比べたのは、2026 年 11 月 10 日に確かめたメモリー機能の公開説明です。OpenAI の製品全体の指示・ツール・権限の仕組みとの比較ではありません。([メモリーの説明](https://learn.chatgpt.com/docs/customization/memories)、[パーソナライズの説明](https://learn.chatgpt.com/docs/personalize))

## 記憶の方針が変わる更新

記憶の扱い方が変わる版に更新すると、エージェントが既にある知識の見直しを始めます。その間は「Upgrading memory…」と進み具合が表示されます。元の出典、あなたが伝えた好み、過去の判断は残したまま、古い手順の訂正や重複の整理を少しずつ進めます。読んだだけでは見直し済みにせず、出典が足りない所は未解決のまま残します。一度見直しが済めば、同じ方針の普通の更新で最初からやり直すことはありません。
