# MCPの知識配送

Markdownの本文は0.28.1から使えます。更新後はMCPを再起動してください。

`shikii_wiki`と`shikii_reflect`の成功応答は、完全なJSONを`structuredContent`へ返し、AI向けの本文をMarkdownで返す場合があります。プログラムからは`structuredContent`を読んでください。`content[].text`はMarkdownか、空白を詰めたJSONです。

shikiiのツールを使う前に、`shikii_wiki`の説明にある共通手順を読んでください。初期化の案内には、その参照先とすぐに必要な規則を残しています。サーバーの案内を各ツールへ付加するクライアントでも、共通手順の全文を1か所で読めます。

ツール結果をAIへ渡す時は、完全な表示を1つ選び、`isError`と必要な状態を保持します。プログラムで扱う時は`structuredContent`を優先し、無い時は元の`content`を保持します。本文がJSONとは仮定しません。構造化された結果に含まれない画像や資料への参照も残します。サーバーは従来どおり両方の形式を返します。

同じreceiptで通常の検索を繰り返す時は、変わらない`collective.notice`を`notice_from`が示す以前の配送へ結ぶ場合があります。共用するのは固定説明だけで、変更・対比・調査の候補、不足の案内、回復先は保持します。以前の応答が文脈に無ければ、同じreceiptとqueryに`reasoning:{depth:focused}`を付けて準備し直すと全文を読めます。読む深さの明示、同版の明示回復、説明の変更、新しいreceiptでは全文を返します。輸送量全体が減る時だけ共用します。

本文は元の値を保持します。教訓の要約、引用の短縮、条件の削除、出典や改訂の参照の変更は行いません。同じ長文が複数回出る時は、原文のまま1つの節へまとめます。他の値は空白を詰めたJSONのメタデータへ保持します。各節には元のフィールドの場所をJSON Pointerで列挙し、UTF-8のバイト数を付けます。その節が列挙する配列のnullは、元の文字列を置く場所です。フィールドの意味・不確実性・信頼の境界は元のままです。

本文を囲む区切りは、原文に含まれる同じ文字の並びより長くします。Markdownの例や引用が節の外へ出ることを防ぎます。JavaScriptで正確に表せる範囲を超えた整数も含め、数値の精度を保ちます。この数値の保持は成功したMCPの構造化応答全体へ適用し、他のツールの本文はJSONの形式を保ちます。

空白を詰めたJSONより512バイト以上小さくなる時だけMarkdownを選びます。それ以外はJSONを返します。このバイト差は表示を選ぶ目安であり、トークン削減や判断精度を保証するものではありません。重複しない本文には共有の節を作りません。1 MiBを超える応答は空白を詰めたJSONにします。深い階層や抽出の上限を超える値もメタデータへ保持します。エラー・他のMCPツール・HTTP/CLI・保存形式は従来どおりです。新しい設定は不要です。

回帰テストは実際のMCPの往復を使い、表示から完全なJSONを独立に復元します。出典の同一性、条件、原文、囲み区切り、JSON Pointerのエスケープ、配列、null、空の値、数値の精度、抽出の上限を確認します。代表的なtokenizerによる測定と変換時間の比較も行います。全情報の保持とモデルの判断精度は別の検証なので、公開先で使うモデルと課題で精度も比較してください。
